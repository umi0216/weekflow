# 同频 · 团队协作

精简的团队任务看板。成员导航、四阶段任务流，操作优先。

- 四阶段：待办 → 进行中 → 待检查 → 已完成。
- 新建任务默认待办，自动记录创建时间。双击待办空白区新建；单击卡片编辑，双击卡片推进，也支持拖动和状态选择。
- 按创建周分组（周一到周日），支持收起、筛选、搜索及列表视图。
- 每位成员有独立空间，全部视图汇总团队任务。
- 看板只显示标题、日期和必要标记；描述、时间记录在详情中查看。
- 常用操作使用图标，悬停查看名称；键盘聚焦和触屏均可操作。
- 示例模式与真实数据库隔离；进入示例不会写入真实数据。
- 数据保存在服务端；任务更新有版本检查，避免多人操作时无提示覆盖。
- 局域网设备私信、附件发送和多人主动加入屏幕观看，从右上角消息图标进入。

## 本地运行

需要 Node.js 22.13 或更新版本，推荐 Node.js 24+（内置 SQLite）。无需安装第三方依赖。

```powershell
npm run dev
```

打开 http://127.0.0.1:4173 。本地数据保存在 `.runtime/team.sqlite`，重启保留。不要删除此文件，定期备份整个 `.runtime` 目录。

如需在可信的公司局域网使用，Linux / macOS 下执行：

```bash
HOST=0.0.0.0 npm run dev
```

其他设备访问 `http://服务器的局域网IP:4173`，不要访问 `0.0.0.0`。环境变量需与启动命令写在同一行，或先用 `export HOST=0.0.0.0` 导出。访问控制由公司网络提供；成员空间用于分类任务，成员姓名不是登录账户。默认本地服务仅监听本机。

```powershell
npm test
npm run build
```

## 局域网消息与文件

打开网站后自动出现在「在线设备」，不注册、不选择待办成员。点击右上角消息图标，先确认对方的 IP 和六位设备短码，再点击其设备；聊天顶部明确显示「发给 IP · 短码」，消息和附件仅发给该设备。

列表只包含打开此网站的浏览器设备，不扫描整段局域网。同一个 IP 下的不同浏览器用短码区分，自己的 IP 和短码显示在设备列表顶部；IP 取自服务器连接地址。浏览器保存匿名设备凭据，刷新或 IP 变化后可恢复会话；清除网站数据、换浏览器会视为新设备。

- Enter 发送，Shift + Enter 换行。
- 先选收件设备，再点击附件图标或拖入文件；单文件最多 100 MB，支持进度和取消。只有双人会话双方可以下载附件。
- 关闭消息面板后，新消息会在入口显示标记。
- 消息保存在 SQLite，文件保存在 `.runtime/files/`。备份整个 `.runtime/`，不要只备份数据库。

## 屏幕共享

点击消息面板顶部「共享」，选择窗口、标签页或整个屏幕。所有在线设备都能看到「谁正在共享」，点击「观看」才加入，不会自动播放。

屏幕共享独立于私信对象：可以给 B 发消息，同时让 B、C 自主加入观看。共享者看到观看人数；观众可单独退出、全屏或重新连接。共享者点击「停止」、停止浏览器捕获或关闭面板，会结束所有人的观看。当前仅传输屏幕画面，不录制，不包含麦克风或远程控制。

浏览器要求屏幕捕获运行在受信任的 HTTPS（或本机 localhost）中，普通 `http://局域网IP` 可发送消息和文件，不能发起屏幕共享。[浏览器要求](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getDisplayMedia)

在服务器生成局域网证书（需要 OpenSSL，将示例 IP 换成服务器实际 IP）：

```bash
npm run cert -- 192.168.1.23
```

将 `.runtime/certs/lan-ca.crt` 导入每台使用设备的「受信任的根证书」；仅分发此 `.crt`，私钥留在服务器。在 Windows 使用 Chrome / Edge 时导入 Windows 的受信任根证书库；其他浏览器按其证书设置导入并信任。

```bash
HOST=0.0.0.0 npm run dev:https
```

访问 `https://192.168.1.23:4173`。也可用 `TLS_CERT`、`TLS_KEY` 指定已有证书；更换 IP 后重新运行证书命令，原有 CA 会保留。

画面使用 WebRTC 在局域网设备间直连，服务器仅交换连接信息，不使用外部 STUN / TURN。无线访客隔离、设备防火墙或禁止 UDP 的网络可能阻止观看。[连接范围](https://developer.mozilla.org/en-US/docs/Web/API/RTCPeerConnection/RTCPeerConnection)

新版本启动时自动迁移本地数据库，原有待办成员和任务保留。此前公共频道记录保留在数据库中，不会混入新的双人会话。

## 验证

```bash
npm test
npm run build
BROWSER_PATH=/本机/Chrome或Chromium路径 npm run test:browser
```

给浏览器命令追加 `-- --https` 可验证 HTTPS。浏览器验证使用临时数据库和文件目录，退出后清理，覆盖同 IP 设备识别、指定收件人、消息与附件隔离、两个观看端主动加入 WebRTC 画面、退出与停止共享和原任务看板。屏幕选择器由测试画面替代，真实屏幕授权仍需在实际设备上确认。

## 构建与部署

`npm run build` 生成 `dist/server/index.js`，是包含前端资源与接口的自包含 Cloudflare Worker，不依赖外部 CDN。构建只生成本地文件，不会上传或发布。

Worker 构建仅包含任务看板；消息、文件和屏幕共享需要运行上述 Node.js 服务及可写数据目录。自行部署 Worker 看板时，配置名为 `DB` 的 Cloudflare D1 数据库绑定，并应用 `drizzle/` 中的 SQL 迁移。D1 与本地 SQLite 是两个独立数据库；访问控制由部署环境配置。

源码可直接提交到自己的 Git 仓库。数据库、测试截图、浏览器缓存、构建产物及本地环境配置均由 `.gitignore` 排除。

快捷键：N 新建任务、/ 搜索、Enter 编辑选中卡片、Ctrl/⌘ + Enter 保存、Esc 关闭弹窗。
